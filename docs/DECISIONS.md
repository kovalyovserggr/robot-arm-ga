# RobotArmGA — проектні рішення (ADR)

Дата фіксації: 2026-07-08. Статус: ухвалено.
Проект: ко-оптимізація конструкції та кінематики рухів роботизованої руки
для операції монтажу деталі на агродрон. Ціль: стаття Scopus (MDPI Machines,
Q2) + розділ дисертації (GA-компонент ієрархічної методології).

## Р1. Архітектура: клієнт-сервер, HTTP REST
- Unity 6 (клієнт, фізичний експеримент) ↔ Python FastAPI (сервер, GA).
- Протокол рушій-агностичний: сервер оперує лише генами і метриками.
- Синхронізація — long polling; сід ГПСЧ фіксується конфігом.
- Статус: реалізовано, наскрізний цикл перевірено (100 поколінь × 50).

## Р2. Симулятор: Unity 6 (PhysX) + крос-валідація в MuJoCo
- Основні експерименти: Unity, ArticulationBody (редукційно-координатний
  солвер PhysX — те саме сімейство, що в NVIDIA Isaac). Фіксований
  timestep, фіксовані сіди, площадки фізично ізольовані.
- Крос-валідація: 5–10 фінальних Парето-оптимальних особин відтворюються
  в MuJoCo як незалежному рушії → підрозділ "Cross-engine validation"
  у статті (знімає зауваження щодо ігрового рушія).
- Побічний внесок статті: engine-agnostic evaluation protocol.

## Р3. Топологія: фіксована, 6 револьютних суглобів (6R)
- Кількість ланок не еволюціонує (геном фіксованої довжини,
  стандартні оператори GA).

## Р4. Конструктивні гени: DH-параметри
- На ланку i: a_i (довжина), α_i (кут скручування осей), d_i (осьове
  зміщення) → 6×3 = 18 генів. Без надлишковості кодування; стандарт,
  зрозумілий рецензентам. В Unity розгортається ланцюжком Transform.

## Р5. Гени руху: ключові кути по фазах (direct encoding, FK)
- 4 фази монтажу (підхід/захоплення → перенесення → позиціонування →
  встановлення) × 6 суглобів = 24 гени; зберігаються нормованими [-1,1],
  розгортаються в кути в межах лімітів суглобів.
- Інтерполяція між ключовими кадрами — драйвами ArticulationBody.
- IK у геномі не використовується (розривний fitness-ландшафт);
  допустиме застосування IK лише для засіву частини початкової популяції.
- Розширення (окремий експеримент): +4 гени тривалостей фаз.
- Разом: 42 гени.

## Р6. Критерії (багатокритеріальна ефективність + надійність)
- T  — час виконання операції;
- E  — енергія: механічна робота, E = Σ_t Σ_i |τ_i·Δθ_i| (моменти
  з ArticulationBody.jointForce; ланки з масою ~ довжині);
- W_cv  — нерівномірність зносу: коеф. варіації накопиченої роботи
  по суглобах (проксі зносу, обґрунтування — модель Арчарда);
- W_max — піковий знос найнавантаженішого вузла.
- Обмеження (не критерій): успішність монтажу в межах допуску точності
  → constrained domination у NSGA-II. Особина, що "не рухається",
  недопустима за визначенням.

## Р7. Метод оптимізації: два етапи
- Етап 1 (baseline): зважена згортка критеріїв, класичний GA.
- Етап 2 (основний): NSGA-II з constraint domination, Парето-фронт.
- Порівняння етапів = окремий підрозділ результатів статті.
- NSGA-III згадується як перспектива (4 критерії — межа комфорту NSGA-II).

## Р8. Популяція 100, площадок 100
Обґрунтування (трикутник обмежень):
1) GA: правило 2–4 × довжина генома (42) → 84–168; NSGA-II потребує
   ~100 для утримання фронту по 4 критеріях (дефолт канонічних робіт Деба);
2) Фізика: 100 рук × 6 суглобів — запас продуктивності PhysX на CPU;
3) Час: площадки ≥ популяції → час покоління не залежить від її розміру;
   цикл ~30 с при timeScale ×10 → ~3 с/покоління → 200 поколінь ≈ 10 хв
   → 10 прогонів різними сідами ≈ 2 год.
Популяція > площадок допустима: оцінка у кілька тактів (протокол готовий).

## Р9. Відтворюваність (вимоги до всіх експериментів)
- Фіксовані: сід сервера, сіди клієнта, Fixed Timestep, версії Unity/пакетів.
- Кожен прогін логовано поколінно (JSON) — сировина для графіків.
- Статистика по ≥10 прогонах з різними сідами; версія коду = git-тег.

## Р10. Позиціонування статті
- Внесок: ко-оптимізація конструкції (DH) та кінематики рухів за
  критеріями ефективності І надійності (рівномірність/пік зносу) з
  constraint-домінуванням NSGA-II, валідована на паралелізованій
  фізичній симуляції збиральної операції + engine-agnostic протокол.
- Related work: 4 табори — (А) траєкторії NSGA-II; (Б) оптимізація
  конструкції; (В) ко-дизайн морфологія+керування; (Г) знос/надійність.
  Gap = (В)∩(Г). Диференціація від робіт про знос: там оптимізується
  розміщення/траєкторія фіксованої машини, тут машина проектується
  під мінімальний і рівномірний знос.
- Ризики рецензування і закриття: sim-only → крос-валідація (Р2) +
  limitations; "ігровий рушій" → PhysX/Isaac аргумент (Р2); спрощений
  знос → чесне проксі + Арчард (Р6); "ще один NSGA-II" → конструктивні
  гени і критерії надійності в назві/анотації (Р10).
- Після перших результатів: перевірити Special Issues Machines
  (evolutionary computation / intelligent maintenance).
