# RobotArmGA — специфікація генома v1.3

Дата фіксації v1.0: 2026-07-08. Оновлено до v1.3: 2026-08-16
(заборонена зона довжини ланки, критерій M, v1.1 умова успіху
позиція+швидкість, path_efficiency). Базується на рішеннях Р3–Р6,
Р11–Р12 (див. DECISIONS.md).

Геном: 42 речові гени, кожен зберігається нормованим g ∈ [-1, 1].
Розгортання у фізичний параметр — ЗАЛЕЖНО ВІД ГРУПИ ГЕНА (§1).
Усі оператори GA (кросовер, гаусова мутація σ, кліпінг) працюють
у нормованому просторі — один масштаб для всіх генів.

## 1. Конструктивні гени (18): DH-параметри

Модифікована конвенція Денавіта–Хартенберга. Ланка i (i = 1..6)
описується трійкою (a_i, α_i, d_i); змінна суглоба — θ_i (револьютний,
вісь z_i). Ланцюжок: зсув по x на a_i → поворот навколо x на α_i →
зсув по z на d_i → суглоб з обертанням навколо (нового) z.

| Індекс | Ген | Фізичний зміст | Формула розгортання | Од. |
|---|---|---|---|---|
| 0–5   | a_1..a_6 | довжина ланки (спільний перпендикуляр осей) | **UnpackLinkLength** (заборонена зона, див. нижче), p_max=0.35 | м |
| 6–11  | α_1..α_6 | кут скручування сусідніх осей | Unpack (лінійне, БЕЗ забороненої зони) | ° |
| 12–17 | d_1..d_6 | зміщення вздовж осі суглоба | **UnpackLinkLength** (заборонена зона), p_max=0.30 | м |

**UnpackLinkLength(g, p_max)** — v1.3 (замінює просте лінійне
розгортання v1.0 для a_i, d_i):
```
g < GeneSplit(=-0.5)  →  довжина = 0                          (злиття)
g ≥ GeneSplit          →  довжина = LinkMinPhysical + t·(p_max−LinkMinPhysical)
                          де t = (g−GeneSplit)/(1−GeneSplit)
```
LinkMinPhysical = 0.05 м (мінімальний фізичний габарит привода).

**Unpack(g, p_min, p_max)** (загальне лінійне, для α і кутів фаз):
```
p = p_min + (g + 1)/2 · (p_max − p_min)
```

Примітки (v1.3):
- Проміжна зона довжини (0, 0.05м) фізично нереалізовна (два приводи
  перекриються) — навмисно вирізана з простору декодування. Це НЕ
  спрощення "для зручності" — злиття (g<GeneSplit) НЕ втрачає ступінь
  волі суглоба θ_i, обнуляється лише геометричне розміщення осі.
- ~25% простору кожного з 12 генів довжини (a_i,d_i) веде до злиття —
  дозволяє GA "відкрити" сферичне зап'ястя (a_4=a_5=0, стандарт
  промислових 6R) БЕЗ жорсткого кодування цієї структури.
- Дзеркало обов'язкове між Python (genome_seed.py: unpack_link_length)
  і C# (GenomeSpec.cs: UnpackLinkLength) — розбіжність ламає M.
- Діапазон α обмежено половиною кола (±90°): α і α±180° у комбінації
  зі знаком θ дають дзеркальні дублікати конфігурацій.
- **ВІДОМИЙ ефект комбінації (Т18):** заборонена зона × мала частка
  засіву (§4, 10%) → значна частка НЕзасіяної популяції фізично
  нереалізовна для досяжності (усі/більшість з 12 генів довжини
  впадають у мертву зону одночасно). Не баг — задокументована
  властивість простору пошуку, кандидат для тюнінгу SEED_FRACTION
  чи GeneSplit у майбутній ревізії.

## 2. Гени руху (24): ключові кути по фазах

Фази монтажу j = 1..4: (1) підхід і захоплення деталі → (2) перенесення
→ (3) позиціонування над точкою монтажу → (4) встановлення.
Ген θ̂_ij задає цільовий кут суглоба i в кінці фази j.

| Індекс | Ген | Фізичний зміст | p_min | p_max | Од. |
|---|---|---|---|---|---|
| 18–23 | θ̂_1j..θ̂_6j, j=1 | цільова поза, кінець фази 1 | −150 | +150 | ° |
| 24–29 | j=2 | цільова поза, кінець фази 2 | −150 | +150 | ° |
| 30–35 | j=3 | цільова поза, кінець фази 3 | −150 | +150 | ° |
| 36–41 | j=4 | цільова поза, кінець фази 4 | −150 | +150 | ° |

- Ліміти ±150° — типові для промислових револьютних суглобів; фіксовані
  (не еволюціонують) у v1.3.
- Стартова поза θ_i(0) = 0 ∀i — однакова для всіх особин (чесний старт).
- Відпрацювання: цільові кути подаються у drive суглоба (PD-модель,
  константи фіксовані §3); перехід між ключовими кадрами — лінійна
  інтерполяція цілі всередині фази (DrivePhases): для t у межах фази j
  тривалістю dur, s=clamp01(t/dur), target=Lerp(попередня_ціль, θ̂_j, s).
- Тривалості фаз фіксовані: t = (2.0, 2.5, 2.5, 2.0) с, цикл 9 с,
  +3 с добігу (SettleAfterCycle) = 12 с максимум на успішну особину;
  30 с — страховий ліміт (PlatformTimeLimit) для невдалих.
- **Стратегії мутації σ (Т4, не гени генома, а параметр GA-оператора):**
  constant / annealing / p_control (лише weighted_sum) / self_adaptive
  (ES-стиль, σ мандрує з особиною, τ=1/√(2·42)). NSGA-II завжди
  використовує SBX+поліноміальну мутацію незалежно від цього поля.

## 4. Ініціалізація популяції

- 90% особин: усі гени ~ U(−1, 1).
- 10% особин (SEED_FRACTION): "засів" — конструкція з рівномірними
  ланками (a_i = 0.2 м, α чергування 0/90°, d_i = 0.05 м) + мутаційний
  шум σ = 0.15; рухи випадкові. Гарантує наявність рук, що фізично
  дістають до деталі й точки монтажу, з першого покоління.
- IK-засів поз (опція, не реалізовано в v1.3): для засіяних конструкцій
  кути фаз 1 і 3 обчислюються CCD-солвером до цілей "деталь"/"точка
  монтажу".
- **Застереження (Т18):** при заборонений зоні §1 та лише 10%-й частці
  засіву значна частка НЕзасіяних 90% може виявитись фізично
  недосяжною (короткий сумарний виліт). Спостережено емпірично на
  реальних прогонах — не завжди перешкоджає успіху популяції загалом
  (Т9-успіхи все одно з'являються), але варте уваги при інтерпретації
  низьких success_rate на ранніх поколіннях.

## 5. Вимірювання критеріїв (клієнт → IndividualResult)

| Поле | Формула вимірювання |
|---|---|
| assembly_time (T) | час від t=0 до success; якщо fail → PlatformTimeLimit (30с) |
| energy (E) | E = Σ_кроків Σ_i \|τ_i·Δθ_i\|; τ = clamp(DriveStiffness·(θ_target−θ) − DriveDamping·θ̇, ±ForceLimit) — PD-модель приводу, ОЦІНКА, бо жива сила драйва в Unity недоступна (jointForce читається нулем) |
| W_i (на суглоб) | накопичена \|τ_i·Δθ_i\| по кроках — вектор 6 значень (joint_work) |
| wear_cv (W_cv) | std(W_1..W_6) / mean(W_1..W_6); якщо mean≈0 → 10 (кліп) |
| wear_max (W_max) | max(W_1..W_6) |
| **M (лише NSGA-II)** | **Σ(a_i + d_i), декодовано ЛИШЕ з construction-генів (не залежить від motion) — критерій парсимонії/матеріаломісткості, Т9** |
| **W_max_over_M (лише NSGA-II)** | **W_max / max(M, 0.05)** — нормалізація зносу на розмір тіла, захист від ділення на ~0 |
| precision_error | якщо захоплено: найкраща (мінімальна) відстань деталь↔ціль за весь прогін (bestPrecision), АБО 1.0 якщо жодного разу не покращилась; якщо НЕ захоплено: 1 + найкраще наближення ефектор↔деталь за прогін; кліп на [0,10] проти NaN/вибухів |
| **path_efficiency (діагностичний, НЕ впливає на fitness)** | **реальна довжина шляху деталі поки захоплена / max(пряма_відстань, 0.01м); 0 якщо не захоплено; 1.0=ідеально пряма, >1.0=зайві рухи** |
| collisions | кількість контактів ланок з об'єктами, ОКРІМ самої деталі (контакт з деталлю — не порушення) |
| success | встановлено в межах поточного допуску curriculum, у фазі≥3, до ліміту часу |

Розширення протоколу (не змінилось з v1.0): IndividualResult
доповнюється полями wear_cv, wear_max, joint_work[6], а з v1.3 —
path_efficiency. Fitness-згортка рахується на сервері з сирих метрик.

## 6. Формула fitness (два варіанти — не частина генома, але критична
для інтерпретації результатів; §Р7/Р12 DECISIONS.md)

**Stage 1, weighted_sum (baseline):**
```
якщо success:  fitness = −eff
               eff = w_T·T/T_ref + w_E·E/E_ref + w_CV·W_cv + w_MAX·W_max/W_ref
якщо fail:     fitness = −(5.0 + 3·precision_error + 0.1·eff)
```
**ВАЖЛИВЕ ОБМЕЖЕННЯ (Т21, підтверджено на n=4 незалежних успішних
чемпіонах):** щойно success=True, precision_error ПОВНІСТЮ випадає з
формули — немає різниці між "ледь пройшов поріг" і "влучив ідеально".
Спостережено емпірично: усі перевірені успішні чемпіони мають запас
точності лише 1.9–3.6мм відносно свого допуску curriculum. Це системна
властивість методу, не одиничний випадок конкретного сіда.

**Stage 2, NSGA-II (основний метод):** constrained domination за 5
критеріями (T, E, W_cv, W_max_over_M, M); недопустима особина (fail)
завжди програє допустимій незалежно від критеріїв (Deb's constraint
handling); серед допустимих — звичайне Парето-домінування +
crowding distance.

## 7. Контрольні цифри

- Розмір генома: 42 (v1.3) / 46 (з тривалостями фаз, не реалізовано).
- Популяція: 100 (Р8). Мутація (weighted_sum): p ≈ 0.08 на ген, σ0=0.15
  (constant) або варіативна (annealing/p_control/self_adaptive, §2).
- NSGA-II: SBX η_c=15, поліноміальна мутація η_m=20.
- JSON одного покоління: 100 × 42 float ≈ 60 КБ — транспорт без змін.
- Config для клієнта: construction_gene_count = 18, motion_gene_count = 24,
  population_size = 100 (задається в Unity Inspector, код не змінюється).
