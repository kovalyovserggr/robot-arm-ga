# GA-оптимізація роботизованої руки: клієнт-серверний каркас

Сервер (Python, FastAPI) — генетичний алгоритм.
Клієнт (Unity, C#) — симуляція покоління: площадки з роботами, монтаж деталі на дрон.

## Протокол (HTTP REST, JSON)

| Метод | Шлях | Призначення |
|-------|------|-------------|
| POST | `/experiment/start` | конфіг → покоління 0 |
| POST | `/experiment/results` | fitness покоління N → покоління N+1 (`done=true` при зупинці) |
| GET | `/experiment/status` | номер покоління + історія збіжності |

Синхронізація природна: клієнт надсилає результати і чекає відповіді,
поки сервер рахує нове покоління (long polling, таймаут у клієнті 120 с).

## Запуск сервера

```bash
cd server
pip install fastapi uvicorn
uvicorn main:app --host 127.0.0.1 --port 8000
```

Swagger UI для ручного тестування без Unity: http://127.0.0.1:8000/docs
Логи кожного покоління падають у `server/logs/gen_XXXX.json` — це сировина
для таблиць і графіків збіжності у статті.

## Підключення в Unity

1. Package Manager → Add package by name → `com.unity.nuget.newtonsoft-json`
2. `GAExperimentClient.cs` — на порожній GameObject у сцені
3. У поле `RunSimulation` підключити власну корутину:
   спавн площадок за геномами → монтаж → виклик `onComplete(results)`.
   Поки її нема — працює вбудована заглушка з фіктивною fitness,
   що дозволяє перевірити зв'язок одразу.

## Куди підключати реальний GA

`server/ga_engine.py` → зберегти сигнатури `init_population()` і
`next_generation()`, замінити нутрощі на оператори з дисертації.
Гіперпараметри винесені полями класу — підуть у таблицю параметрів статті.

## Відтворюваність (важливо для Scopus)

`seed` у конфігу фіксує ГПСЧ сервера. Для повної відтворюваності
зафіксуй також фізичний timestep у Unity (Project Settings → Time →
Fixed Timestep) і сід генераторів на боці клієнта.
